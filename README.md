# Gastro Hub

## О проекте

Учебный проект по проектированию PostgreSQL-базы данных для сети заведений общественного питания и выполнению аналитических SQL-запросов.

В проекте реализованы создание структуры базы данных, загрузка данных о ресторанах, менеджерах и продажах, а также аналитические запросы для работы с показателями заведений и их меню.

Основные задачи проекта:

* спроектировать реляционную структуру базы данных;
* загрузить данные из исходных таблиц;
* выполнить аналитические расчёты с помощью SQL;
* работать с полями `JSONB`;
* реализовать изменение данных и структуры таблиц с использованием транзакций.

## Структура данных

В базе создана схема `cafe`, включающая:

* `restaurants` — информация о заведениях, их типах и меню;
* `managers` — информация о менеджерах;
* `restaurant_manager_work_dates` — связь менеджеров с заведениями и периоды их работы;
* `sales` — данные о продажах и среднем чеке.

Для меню используется тип `JSONB`, что позволяет хранить категории блюд и их цены в структурированном JSON-формате.

Данные загружаются из исходных таблиц `raw_data.sales` и `raw_data.menu` с формированием связей между заведениями, менеджерами и продажами.

## Что реализовано

* спроектирована реляционная схема базы данных с первичными и внешними ключами;
* реализована загрузка данных из нескольких источников в целевые таблицы;
* рассчитан **топ-3 заведений каждого типа по среднему чеку** с использованием оконной функции `ROW_NUMBER()`;
* создана материализованная витрина для анализа динамики среднего чека по годам;
* рассчитана динамика среднего чека относительно предыдущего года;
* определён топ-3 заведений по количеству менеджеров;
* определено заведение с наибольшим количеством позиций пиццы;
* найдено самое дорогое блюдо категории «Пицца» для каждого заведения;
* реализовано изменение цены капучино на 20% с использованием `JSONB` и транзакции;
* выполнена миграция телефонных номеров менеджеров из отдельного поля в массив `JSONB`.

## Аналитические запросы

Для обработки данных используются:

* CTE;
* оконные функции `ROW_NUMBER()`, `RANK()` и `LAG()`;
* агрегатные функции;
* `JOIN`;
* `JSONB`-операторы и функции;
* `CROSS JOIN LATERAL`;
* материализованные представления.

Например, динамика среднего чека рассчитывается путём сравнения текущего значения со значением предыдущего года с помощью `LAG()`. Результат сохраняется в materialized view `cafe.check_dynamics`.

Для работы с меню используются функции `jsonb_each()` и `jsonb_each_text()`, позволяющие получать отдельные категории и позиции меню из JSONB.

## Работа с транзакциями

Изменения данных выполняются внутри транзакций `BEGIN ... COMMIT`.

При изменении цены капучино используется блокировка строк `FOR NO KEY UPDATE`, после чего значение в JSONB-структуре меню обновляется с помощью `jsonb_set()`.

Также реализована миграция телефонных номеров менеджеров: создаётся поле `phones JSONB`, существующие номера преобразуются в JSONB-массив, после чего исходное поле удаляется.

## Результат

В результате создана PostgreSQL-база данных для хранения и анализа информации о заведениях, меню, менеджерах и продажах.

Проект демонстрирует навыки:

* проектирования реляционной базы данных;
* написания сложных SQL-запросов;
* работы с оконными функциями и CTE;
* работы с полуструктурированными данными в JSONB;
* создания materialized view;
* выполнения транзакционных изменений данных;
* использования блокировок при изменении данных.

## Выводы

Проект позволил объединить данные о заведениях, продажах и менеджерах в связанной структуре и подготовить SQL-решения для различных аналитических задач.

В ходе работы были отработаны как аналитические запросы, так и операции изменения структуры и содержимого базы данных, включая работу с JSONB и транзакциями.

## Системные требования

Для выполнения скриптов необходимы исходные таблицы в схеме `raw_data`, в частности `raw_data.sales` и `raw_data.menu`.
